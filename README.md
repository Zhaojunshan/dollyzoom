## Stack

- Next.js (App Router) static export + TypeScript + Tailwind CSS v4
- Original sample still and clip in `public/demo/` (generated by `scripts/make-demo-media.py`)
- Watermarked in-browser preview, only after the moderation proxy allows it
- `server/` — Node (or Cloudflare Worker) proxy that holds `CREEM_API_KEY`

`output: "export"` cannot host API routes. Do not add a `basePath`. Production leaves `NEXT_PUBLIC_BASE_PATH` empty.

## Creem content moderation

Every generate click screens the dolly-zoom prompt **before** a preview is shown. `deny`, `flag`, timeouts, and HTTP errors fail closed. The key never ships in the Pages bundle.

The static site reads `public/moderation.json`:

```json
{ "endpoint": "" }
```

Leave `endpoint` empty until the proxy below is deployed. An empty value fails closed (no preview). After deploy, set it to the proxy’s public URL, including the path:

```json
{ "endpoint": "https://YOUR-HOST/v1/generate" }
```

Commit that URL (it is not secret) and let Pages redeploy.

### Where to put `CREEM_API_KEY`

1. Creem Dashboard → **Settings → API Keys**.
2. Create a **live** key. The prefix must be `creem_`. A `creem_test_` key does not count for account review.
3. Store it only as the environment variable `CREEM_API_KEY` on the proxy host. Do not commit it, do not put it in `public/moderation.json`, and do not add a `NEXT_PUBLIC_` copy.

`server/env.example` lists the variable names. `GET /health` reports `{"key":"live"}` or `{"key":"missing"}` and never the key itself.

### Run the proxy

Node, from this repo:

```bash
CREEM_API_KEY="creem_..." npm run moderation-proxy
```

The process listens on `$PORT` or `8787`.

Docker, context = repository root:

```bash
docker build -f server/Dockerfile -t dollyzoom-moderation .
docker run --env CREEM_API_KEY -p 8787:8787 dollyzoom-moderation
```

Cloudflare Workers:

```bash
cd server
npx wrangler secret put CREEM_API_KEY
npx wrangler deploy
```

Confirm a real call before asking Creem to re-review:

```bash
curl -sS https://YOUR-HOST/health
# then on https://dollyzoom.top upload a photo and click Generate
```

That click must reach `POST https://api.creem.io/v1/moderation/prompt` with header `x-api-key`. Sandbox (`test-api.creem.io` / `creem_test_`) does not satisfy review. `CREEM_ALLOW_TEST_KEY=1` exists only for local experiments and must stay unset in production.

The proxy allows browser calls from `https://dollyzoom.top`, `https://www.dollyzoom.top`, and localhost only.

This static site has no accounts, so it cannot open those wallets yet. The proxy returns `moderationId` for that debit. In the Creem dashboard, on the existing product `prod_w9pGaP1bfoaF20iNiGXKt` (do not change the id): **Products → Delivery → Add → New AI generation credits**, with moderation required. Do not also grant those credits from a webhook. Wiring per-user debits needs a signed-in app, which GitHub Pages cannot host.
