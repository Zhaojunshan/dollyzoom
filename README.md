# DollyZoom — AI Dolly Zoom Generator

Upload one photo, get a Hitchcock dolly zoom. The public site is a Next.js static export on GitHub Pages at **https://dollyzoom.top/** (domain root, no `/dollyzoom` prefix).

HD checkout uses the existing Creem product and must stay on this link:

`https://www.creem.io/payment/prod_w9pGaP1bfoaF20iNiGXKt`

Support: `Zjs315416174@gmail.com`. Operator: junshan zhao.

## Stack

- Next.js (App Router) static export + TypeScript + Tailwind CSS v4
- Original sample still and clip in `public/demo/` (generated by `scripts/make-demo-media.py`)
- Watermarked in-browser preview, only after the moderation proxy allows it
- `server/` — Node (or Cloudflare Worker) proxy that holds `CREEM_API_KEY` and `DASHSCOPE_API_KEY`

`output: "export"` cannot host API routes. Do not add a `basePath`. Production leaves `NEXT_PUBLIC_BASE_PATH` empty.

## Creem content moderation

Every generate click screens the dolly-zoom prompt **before** a preview is shown. `deny`, `flag`, timeouts, and HTTP errors fail closed. The key never ships in the Pages bundle.

The static site reads `public/moderation.json`:

```json
{ "endpoint": "" }
```

Leave `endpoint` empty until the proxy below is deployed. An empty value fails closed (no preview). After deploy, set it to the proxy’s public URL, including the path:

```json
{ "endpoint": "https://YOUR-HOST/v1/generate" }
```

Commit that URL (it is not secret) and let Pages redeploy.

### Where to put `CREEM_API_KEY`

1. Creem Dashboard → **Settings → API Keys**.
2. Create a **live** key. The prefix must be `creem_`. A `creem_test_` key does not count for account review.
3. Store it only as the environment variable `CREEM_API_KEY` on the proxy host. Do not commit it, do not put it in `public/moderation.json`, and do not add a `NEXT_PUBLIC_` copy.

`server/env.example` lists the variable names. `GET /health` reports `{"key":"live"}` or `{"key":"missing"}` and never the key itself.

### Run the proxy

Node, from this repo:

```bash
CREEM_API_KEY="creem_..." \
CREEM_WEBHOOK_SECRET="..." \
CREEM_SESSION_SECRET="..." \
DASHSCOPE_API_KEY="..." \

```

The process listens on `$PORT` or `8787`.

Docker, context = repository root:

```bash
docker build -f server/Dockerfile -t dollyzoom-moderation .
docker run --env CREEM_API_KEY --env CREEM_WEBHOOK_SECRET --env CREEM_SESSION_SECRET --env DASHSCOPE_API_KEY -p 8787:8787 dollyzoom-moderation
```

Cloudflare Workers:

```bash
cd server
npx wrangler secret put CREEM_API_KEY
npx wrangler secret put CREEM_WEBHOOK_SECRET
npx wrangler secret put CREEM_SESSION_SECRET
npx wrangler secret put DASHSCOPE_API_KEY
npx wrangler deploy
```

`DASHSCOPE_API_KEY` is a Worker secret, not a `[vars]` entry. Create it in Alibaba Cloud Model Studio (Bailian) for the China (Beijing) region. Do not commit the value. Paid HD calls `wan2.6-i2v-flash` on `https://dashscope.aliyuncs.com` unless `DASHSCOPE_BASE_URL` or `DASHSCOPE_REGION` says otherwise.

Confirm a real call before asking Creem to re-review:

```bash
curl -sS https://YOUR-HOST/health
# then on https://dollyzoom.top upload a photo and click Generate
```

That click must reach `POST https://api.creem.io/v1/moderation/prompt` with header `x-api-key`. Sandbox (`test-api.creem.io` / `creem_test_`) does not satisfy review. `CREEM_ALLOW_TEST_KEY=1` exists only for local experiments and must stay unset in production.

The proxy allows browser calls from `https://dollyzoom.top`, `https://www.dollyzoom.top`, and localhost only.

### Customer credits

Paid HD generation uses a Creem **generation wallet**. This repo does not store a credit balance. Creem is the ledger.

There is no login. Checkout collects the email and creates the Creem customer. After payment, Creem redirects to `https://dollyzoom.top/` with a signed query string. The homepage posts that query to the Worker, which checks the signature, sets `external_id` when the customer does not have one, and ensures a wallet named `generation`. The browser keeps a 7-day HMAC session in `localStorage`. Balance is read from Creem on each visit. Losing site data means opening the success return again (or buying again) to bind this browser. That is the whole identity model.

The static **Buy HD — $1.49** link is unchanged: `https://www.creem.io/payment/prod_w9pGaP1bfoaF20iNiGXKt`. A browser that already has a session can also open a checkout tied to that same customer (`POST /v1/credits/checkout`) so a later purchase lands in the same wallet. `POST /v1/generate` is the free watermarked preview and does **not** debit. It stays an in-browser CSS preview. It does not call Wanxiang or DashScope.

`POST /v1/generations` is the paid path: balance, then Moderation API, then debit 1 generation credit with that moderation id, then Wan image-to-video. The model is `wan2.6-i2v-flash`. Defaults are `720P`, 5 seconds, and `parameters.audio: false` (this model bills a silent clip only when audio is explicitly false). `WAN_RESOLUTION` (`480P`, `720P`, or `1080P`), `WAN_DURATION` (2–15), and `WAN_AUDIO` (`true` or `false`) change those three settings. An unknown value stays on the default. The moderated prompt is sent with `prompt_extend: false`. Upload-only generations use one fixed sentence: the camera quickly pushes in while the lens zooms wider, so the background perspective stretches and the person stays the same size. Wan has no separate motion-strength parameter. `shot_type` applies only when `prompt_extend` is true, so it is left unset and the prompt itself asks for one continuous moving shot. If the task is not accepted, the Worker reverses that debit. A later `FAILED` or `CANCELED` query reverses it too. `UNKNOWN` means the 24-hour task window has passed; that does not refund a clip that already succeeded. This code never grants purchased credits.

Video generation is asynchronous. The paid response does not contain the mp4. It contains `generation.ticket` and `generation.taskId` while `generation.status` is `processing`. The site stores that ticket in `localStorage` and polls `POST /v1/generations/status` about every 8 seconds. When DashScope reports `SUCCEEDED`, that poll returns `generation.videoUrl`, an https OSS link the page plays in a `<video>` element. DashScope says that link expires in about 24 hours. The page also offers **Save video**, which is `GET /v1/generations/file?ticket=…`. That request checks the task again and streams the current mp4 as `dollyzoom-hd.mp4`. Save it before the link expires. Leaving the tab is fine: reopening the site on the same browser resumes the poll, which is also what refunds a failed render. A provider timeout while polling stays `processing` and does not reverse the debit.

The default API host is the Beijing endpoint `https://dashscope.aliyuncs.com`, which matches a China Bailian key. `DASHSCOPE_REGION=singapore` uses `https://dashscope-intl.aliyuncs.com`. `DASHSCOPE_BASE_URL` overrides the host, including a workspace domain such as `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com`. The key, model, and host must be the same region.

Purchased credits are added by Creem when the product grants AI generation credits. The Worker never calls the credit endpoint for a purchase. `checkout.completed` only binds the customer and wallet. `credits.granted` is acknowledged and ignored.

| Path | Role |
| --- | --- |
| `GET /health` | Key class, whether credits secrets are set, and `testGrant: true` only while the temporary grant is on. Never returns secret values. |
| `POST /v1/generate` | Free preview. Screen only. |
| `GET /v1/credits` | Live wallet balance for the browser session. |
| `POST /v1/credits/claim` | Verify the checkout return query and issue a session. |
| `POST /v1/credits/checkout` | Customer-bound checkout, or the static $1.49 link when there is no session. |
| `POST /v1/credits/test-grant` | Temporary. Exists only when `TEST_GRANT_ENABLED` is `1`. Grants 2 generation credits and a session. |
| `POST /v1/generations` | Paid path. Debits only after an `allow` result, then starts Wan. |
| `POST /v1/generations/status` | Poll a paid task. Returns the video URL, or reverses the debit if the task failed. |
| `GET /v1/generations/file` | Download the current mp4 while the DashScope link is still valid. |
| `POST /v1/creem/webhook` | Signed Creem webhooks. Does not grant credits. |

#### Environment variables

Set these on the Worker. Do not commit values.

| Name | Purpose |
| --- | --- |
| `CREEM_API_KEY` | Live key, prefix `creem_`. Same key as moderation. |
| `CREEM_WEBHOOK_SECRET` | Signing secret from Developers → Webhooks. |
| `CREEM_SESSION_SECRET` | Random string, at least 16 characters (`openssl rand -hex 32`). Signs the browser session only. |
| `GENERATION_CREDIT_COST` | Credits debited per paid HD attempt. Default `1`. This does not change what a purchase grants. |
| `CREEM_SUCCESS_URL` | Optional. Must be `https://dollyzoom.top/`, `https://www.dollyzoom.top/…`, or localhost. Default `https://dollyzoom.top/`. |
| `CREEM_ALLOW_TEST_KEY` | Leave unset in production. |
| `TEST_GRANT_ENABLED` | Temporary plain-text var. Leave unset. Set to `1` only to grant 2 test generation credits, then remove it and deploy. |
| `DASHSCOPE_API_KEY` | Beijing Bailian key. Required for paid HD. Never commit it. |
| `DASHSCOPE_REGION` | Optional. `beijing` (default) or `singapore`. |
| `DASHSCOPE_BASE_URL` | Optional https origin. Overrides the region host. |
| `WAN_RESOLUTION` | Optional. `480P`, `720P` (default), or `1080P`. |
| `WAN_DURATION` | Optional integer seconds, 2–15. Default `5`. |
| `WAN_AUDIO` | Optional. `true` or `false`. Default `false` (silent). |

`GET /health` returns `"video":"ready"` only when `DASHSCOPE_API_KEY` is non-empty. It never returns the key. `"credits":"ready"` does not mean the video key is set.

`server/env.example` lists the names. `GET /health` returns `"credits":"ready"` only when the API key is allowed and both secrets are set.

Do this from a machine that is logged into Cloudflare. This change does not deploy it.

```bash

npx wrangler secret put CREEM_API_KEY
npx wrangler secret put CREEM_WEBHOOK_SECRET
```

#### Temporary test credits

Live checkout can show “Live Payments Not Enabled” while the store is under review. This path lets the store owner put **2** generation credits on one Creem customer and open a browser session, then press **Generate HD**. It is off unless the plain-text Worker var `TEST_GRANT_ENABLED` is exactly `1`.

While it is on, `GET /health` includes `"testGrant": true` and nothing else about the grant. The upload section shows **Add 2 test credits**. That button calls `POST /v1/credits/test-grant`. The Worker looks up `hd-test@dollyzoom.top` (`GET /v1/customers?email=`), creates that customer with `external_id` `dzu_owner_hd_test` when it is missing, ensures the `generation` wallet, and credits **2** with Creem’s credit API. The browser saves the returned session and shows the balance. Purchased credits are still applied only by Creem. Webhooks still do not credit the wallet.

The same click is idempotent while that wallet still has at least 2 credits. Creem’s own transactions for this grant cap successful grants at 5 (10 credits). Each IP is also limited to 8 requests a minute. The request body is ignored. There is no second ledger in this repo.

Turn it off as soon as the test is done. A deploy from this `wrangler.toml` does not set the var, and a later deploy replaces Worker vars with the file, so the switch does not survive a normal deploy.

1. On a machine logged into Cloudflare, edit `server/wrangler.toml` locally and add this under `[vars]`. Do not commit that line.

   ```toml
   TEST_GRANT_ENABLED = "1"
   ```

2. Deploy the existing Worker and confirm the flag. The response must not contain the API key or the session secret.

   ```bash
   cd server
   npx wrangler deploy
   curl -sS https://dollyzoom-moderation.eight-grenadilla.workers.dev/health
   ```

3. Publish the site (GitHub Pages on `main`) so the button is in the upload section. Open https://dollyzoom.top/, click **Add 2 test credits**, then upload a photo and press **Generate HD**.

4. Remove `TEST_GRANT_ENABLED` from `wrangler.toml` and deploy again. `health` no longer includes `testGrant`. `POST /v1/credits/test-grant` returns 404, and the button stays hidden.

Do not store `TEST_GRANT_ENABLED` with `wrangler secret put`. Do not point this Worker at `test-api.creem.io` or a `creem_test_` key. Leave product `prod_w9pGaP1bfoaF20iNiGXKt` unchanged. While the flag is on, anyone who can open the site can use the same promo wallet, so keep the window short.
